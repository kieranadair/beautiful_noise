# Schema snapshot

Committed DDL for `BEAUTIFUL_NOISE.DATA`, generated by `sql/dump_ddl.py`.

This exists so the schema is reviewable in the same place as the code that depends on it —
`.context/*.md` is gitignored, drifts, and is explicitly "not ground truth". These files are.

```
tables/     one file per table
views/      POSTER_GALLERY_V
tasks/      CLEANUP_ORPHANED_STAGE_FILES (currently suspended)
stages.md   descriptive — GET_DDL doesn't support stages
```

## Read this before applying anything here

**These files are a record, not a migration.** `GET_DDL` emits `CREATE OR REPLACE`, so running
one against a live schema **drops and recreates the object** — for a table, that means losing
every row. Nothing in this folder should be piped at a live database.

Two specific traps:

- **`views/poster_gallery_v.sql` drops its grants when replaced.** After any rebuild you must
  re-`GRANT SELECT` on the view to both the app role and the admin role, or the deployed app
  breaks on its next query. Role names are in `.context/` (gitignored), not here.
- **The view's CTE structure is load-bearing.** `CREDITS` is pre-aggregated before the join
  because `BANDS`/`HEADLINERS`/`SUPPORTS` use non-`DISTINCT` `ARRAY_AGG`; a naive credits join
  fans out and duplicates those arrays. Preserve it if you rewrite the view.

## Refreshing

```
python sql/dump_ddl.py
```

Reads `.streamlit/secrets.toml` (gitignored) and rewrites this folder in place. Re-run it after
any schema change so the snapshot doesn't rot — a stale snapshot is worse than none, because it
looks authoritative.

Unlike the read-only `SHOW` commands used for auditing, `GET_DDL` runs as a query and will
briefly resume the warehouse. `COMPUTE_WH` is X-Small on a 60s auto-suspend, so this costs cents.

## What is deliberately not here

- **Grants, roles and privileges.** This repository is public. Role and privilege topology stays
  in `.context/` (gitignored). The dump script does not emit them.
- **`BEAUTIFUL_NOISE.STAGING`.** A zero-copy clone belonging to the admin app, last refreshed
  before the 2026-07-12 credits migration — it has no `CREDITS` or `POSTER_CREDITS` table and
  38 posters against DATA's 47. It is not tracked here and should not be treated as current.
- **Data.** `GET_DDL` emits structure only.

## Known legacy in the snapshot

`DESIGNERS` and `POSTERS.DESIGNER_ID` are the frozen single-designer model, superseded by
`CREDITS`/`POSTER_CREDITS`. New uploads leave `DESIGNER_ID` at its default of 1. They remain only
so the un-migrated admin app keeps loading; dropping them is a pending fast-follow.
